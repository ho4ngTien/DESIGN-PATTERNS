# Design Patterns Overview

Design patterns are reusable design vocabulary, not copy-paste classes. A good example starts with a recurring design problem, shows the pressure in a naive design, and then uses a pattern where its trade-offs are justified.

This repository keeps each GoF pattern isolated in its own package so the reader can inspect one idea at a time.

## Reading a Pattern

1. Read the problem and the naive alternative.
2. Identify the responsibility or dependency that is changing.
3. Inspect the pattern roles in the code.
4. Run the demo and tests.
5. Compare the trade-offs before choosing the pattern elsewhere.
